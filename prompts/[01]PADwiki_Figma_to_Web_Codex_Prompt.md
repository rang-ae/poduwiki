# PADwiki | Figma → HTML/CSS/JS 구현 요청서

## 0. 최우선 목표

Figma에서 완성한 PADwiki 인물 소개 페이지를 **디자인 변경 없이, 실제 브라우저에서 원본과 최대한 동일하게 보이도록** 구현해 주세요. 참고해서 비슷하게 만드는 것이 아니라 **픽셀 단위의 시각적 일치**가 목표입니다.

- **Desktop 원본:** https://www.figma.com/design/dtXYwFy0fmH24ZP2yQmnis/?node-id=19-2 (노드 `19:2`, 1440px)
- **Mobile 원본:** https://www.figma.com/design/dtXYwFy0fmH24ZP2yQmnis/?node-id=42-6 (노드 `42:6`, 390px)
- **작업 폴더:** `C:\Users\변혜인\Desktop\DUCK CHILL\padwiki`
- **기술:** HTML5, CSS3, Vanilla JavaScript (ES6+). React/Vue/Next.js, Tailwind/Bootstrap 사용 금지.

**절대 금지:** 디자인 재해석, 임의 개선, 텍스트 요약·수정, 요소 추가·삭제, 원본 이미지의 임의 대체·재생성, 확인하지 않은 치수 추측. 기존 폴더 파일도 확인 없이 삭제하지 마세요.

## 1. 구현 전 Figma 분석

코드를 작성하기 전에 Figma MCP에서 **두 노드의 디자인 컨텍스트, 메타데이터, 스크린샷, 에셋**을 실제로 읽어 주세요. 다음을 기록하고 그대로 반영합니다.

- 프레임/섹션/컴포넌트의 크기와 좌표, 컨테이너 너비
- Auto Layout, padding, margin, gap, 정렬 및 반응형 동작
- 색상 HEX, 테두리, radius, 그림자
- 폰트, 굵기, 크기, 행간, 자간, 텍스트와 줄바꿈
- 원본 이미지·로고·아이콘과 크롭 방식
- 섹션 순서, 정보표의 모든 행, 전체 문구 및 링크 스타일

Figma 접근 또는 에셋 추출이 실패하면 추측해서 진행하지 말고 막힌 항목을 보고해 주세요.

## 2. 프로젝트 구조

별도 빌드 없이 브라우저에서 실행할 수 있게 만듭니다.

```text
padwiki/
├── index.html
├── css/
│   ├── style.css
│   └── responsive.css
├── js/
│   └── main.js
├── assets/
│   ├── images/
│   ├── icons/
│   └── fonts/
└── README.md
```

기존 파일이 있으면 먼저 확인하고, 필요한 경우에만 추가 파일을 만드세요. 하나의 HTML 문서를 CSS 미디어쿼리로 반응형 처리합니다.

## 3. Desktop: 1440px / 노드 19:2

Desktop Figma를 **유일한 시각적 기준**으로 삼아 다음 요소를 빠짐없이 구현하세요.

- 상단 PADwiki 헤더, 로고, 내비게이션, 검색, 사용자 메뉴
- 문서 제목, 수정 정보, 문서 기능 메뉴
- 인물 프로필 카드: 보라색 헤더, 사진, 모든 정보표 행
- `1. 개요`, `2. 상세`, `3. 여담`의 제목·구분선·본문·강조문·스포일러 경고·목록
- 오른쪽 사이드바의 모든 카드와 내용

본문과 사이드바의 폭, 좌표, 간격, 이미지 크롭, 정보표 셀 padding과 행 높이를 **Figma 실측값**으로 구현하세요. 모바일 UI가 데스크톱에 중복 표시되면 안 됩니다.

## 4. Mobile: 390px / 노드 42:6

**모바일은 데스크톱을 축소해서 만들지 마세요.** 이미 완성된 Mobile Figma 프레임을 그대로 구현합니다.

- 모바일 헤더 높이 56px, PADwiki 로고·검색·메뉴 아이콘
- 문서 제목·기능·프로필 카드·정보표·본문 섹션의 **모바일 원본 순서와 배치**
- 모바일 이미지 비율·크롭, 텍스트 줄바꿈, 정보표 열 너비 및 행 높이 일치
- 390px에서 시각적 일치를 우선하고, 360/375/430px에서도 잘림과 가로 스크롤 방지

권장 반응형 구간은 Mobile `<768px`, Tablet `768~1023px`, Desktop `≥1024px`입니다. 이는 구현용 기준일 뿐이며, **1440px/390px에서는 반드시 해당 Figma 프레임이 우선**입니다. 중간 너비는 원본 스타일을 보존하며 자연스럽게 연결하세요.

## 5. 에셋 및 텍스트 보존

- 프로필 사진은 **Figma에 있는 원본**을 사용하고 다른 사진으로 교체하거나 생성하지 마세요.
- 벡터 아이콘은 가능하면 원본 SVG를 추출하세요.
- 폰트는 Figma에 지정된 폰트를 확인하여 합법적으로 사용할 수 있는 방식으로 적용하세요. 대체가 불가피하면 보고하세요.
- 모든 텍스트, 띄어쓰기, 문장부호, 섹션 순서, 프로필 데이터, 여담 항목을 원본 그대로 보존하세요.
- CSS에서 임의의 미적 개선, 새 카드 스타일, 추가 애니메이션을 만들지 마세요.

## 6. 동작과 접근성

원본 UI에 존재하는 기능에 한해 Vanilla JavaScript로 구현하세요.

- 모바일 메뉴 및 검색 UI 열기/닫기
- 문서 섹션 접기/펼치기
- 실제 존재하는 내부 앵커 이동

백엔드가 필요한 기능은 작동하는 척하지 말고 구현 범위를 명시하세요. 시맨틱 HTML, 이미지 alt, 버튼·링크 구분, 키보드 접근성, 적절한 `aria-*` 속성을 적용하되 **시각적 디자인을 바꾸지 마세요**.

## 7. 픽셀 단위 비교 검수: 필수

**코드를 작성한 것만으로 완료 처리하지 마세요.** 실제 브라우저 스크린샷을 Figma 스크린샷과 비교하고 오차를 수정해야 합니다.

1. Figma Desktop(1440px) 및 Mobile(390px) 스크린샷 확보
2. 로컬 웹페이지를 동일한 뷰포트로 열고 스크린샷 촬영 (가능하면 Playwright 사용)
3. 프레임과 브라우저의 캡처 범위·스크롤 위치를 일치시켜 비교
4. 다음 순서로 수정: **전체 레이아웃 → 이미지/카드 → 폰트/줄바꿈 → 색상/테두리 → 세부 여백/아이콘**
5. 수정 후 다시 촬영하고 반복 검수
6. 추가로 360px, 375px, 430px 및 태블릿 너비에서 잘림·가로 스크롤 확인
7. 콘솔 오류, 깨진 에셋, 누락된 콘텐츠 확인

브라우저와 Figma 간 렌더링 차이로 완벽한 일치가 불가능한 부분은 숨기지 말고 명시하세요. 비교를 실제로 수행하지 않았다면 수행했다고 보고하지 마세요.
